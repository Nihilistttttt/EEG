================================================================================

功能1: BDF通道头部按字段类型排列 (eeg_record.c)
  - 问题: MCU端write_header按通道排列(ch0完整256B→ch1完整256B...),
    但EDF/BDF标准要求按字段类型排列(所有通道标签连续→所有transducer连续→...)
  - MNE-Python的_read_edf_header按字段类型连续读取, 与MCU写入方式不匹配, 无法读取
  - 修复: write_header通道头部改为按字段类型排列
    label: 256+ch*16, transducer: 384+ch*80, units: 1024+ch*8,
    phys_min: 1088+ch*8, phys_max: 1152+ch*8, dig_min: 1216+ch*8,
    dig_max: 1280+ch*8, prefilter: 1344+ch*80, samples: 1984+ch*8
  - 验证: MNE-Python成功读取修复后BDF, 8通道/250Hz/21秒/数据形状(8,5250)全正确

功能2: 三端BDF解析同步修改 (Python+安卓)
  - BdfReader.java: 通道头部解析偏移从i*256改为按字段类型(832+i*8等)
  - exercise_Data_unified.py(两个): BDF解析偏移同步修改
  - fix_bdf_header.py: 新建, 旧格式BDF→新格式转换工具
  - verify_bdf.py: 新建, MNE-Python标准流程BDF验证脚本

功能3: 去直流方式从减均值改为1Hz高通滤波 (三端同步)
  - 问题: 离线BDF查看用seg-mean(seg)减窗口均值, 与实时显示效果不一致
    减均值只去DC不去低频漂移, 窗口滑动时波形跳变
    实测: 减均值后std=8314μV(漂移保留), 高通后std=116μV(干净脑电)
  - 标准做法: 对整段数据做1Hz Butterworth二阶零相位高通滤波(filtfilt),
    再截取窗口显示, 与MNE-Python/EEGLAB标准一致
  - Python端(两个exercise_Data_unified.py):
    添加scipy.signal.butter/filtfilt导入, 加载BDF时预计算bdf_data_hp,
    显示时若勾选去直流则用滤波后数据替代减均值
  - 安卓端(BdfReader.java):

2026-08-07  SSVEP显示卡顿优化(三角递推+RunPending后移)
================================================================================

问题: SSVEP闪烁时每隔一段时间卡顿, 卡顿后帧率变快一下然后恢复正常
  - 引入音频播放前不卡顿, 引入音频后出现
  - 音频播放结束一会后间歇性卡顿
  - 卡顿后帧率变快是ssvep_mode_step的target补帧机制(阻塞后连续不等待追上时序)

根因: V5F SSVEP FBCCA分析每2s触发一次, 阻塞主循环
  - ssvep_analyze()中ssvep_generate_refs对每个样本调用sinf+cosf
  - 4目标×3偏移×4子带=48次调用, 每次5000次sinf/cosf = 240,000次
  - 在400MHz下约90ms, 加上CCA矩阵运算总计约100ms
  - RunPending在ssvep_mode_step之前执行, 100ms阻塞延迟SSVEP帧发送
  - 引入音频前100ms停留可能不明显(15Hz太快), 音频改变时序后变可感知

优化1: 三角递推公式替代逐点sinf/cosf (dualcore_v5f_ssvep.c)
  - ssvep_generate_refs: 对固定频率, 角度等差递增
  - sin(a+δ)=sin(a)cos(δ)+cos(a)sin(δ), cos(a+δ)=cos(a)cos(δ)-sin(a)sin(δ)
  - 每次调用从5000次sinf/cosf降为4次sinf/cosf+5000次乘加递推
  - FBCCA分析从约100ms降到约10ms (加速约10倍)

优化2: RunPending移到ssvep_mode_step之后 (V5F/User/main.c)
  - 原顺序: MainLoopProcess → RunPending → handle_ipc_cmd → ssvep_mode_step
  - 新顺序: MainLoopProcess → handle_ipc_cmd → ssvep_mode_step → RunPending
  - SSVEP分析在显示帧发送之后执行, 10ms被下一次while等待吸收
  - 15Hz半周期33ms: 22ms发送+11ms等待, 10ms分析后下一帧while等待1ms, 不卡顿
  - 17Hz半周期29ms: 22ms发送+7ms等待, 10ms分析后轻微延迟3ms(2帧恢复), 可接受

2026-08-07  V5F SSVEP 2秒toggle重置BUG修复: 消除周期性白闪(用户核心症状)

2026-08-04  SD卡SPI驱动实现(初始化/写/读/校验全通过)
================================================================================

更新内容:
1. SD卡SPI驱动完整实现(sd_card.c/h), 基于SPI1, 引脚: SCK=PA5 AF5, MOSI=PA7 AF5,
   MISO=PF9 AF3, CS=PB0(软件管理), CD=PC3(卡插入检测,低有效)
2. SPI模式: Mode3(CPOL=High, CPHA=2Edge), 初始化阶段Mode7(低速≤400kHz),
   初始化完成后切换Mode4(6.25MHz)
3. MOSI空闲管理(关键修复):
   - 新增SD_MOSI_ToAF()/SD_MOSI_ToIdle(): 不发数据时MOSI切为INPUT_PU保持高电平,
     只在发命令/数据字节时切回AF_PP
   - SD卡SPI协议要求MOSI空闲必须为高; CH32H417的SPI外设在AF模式下MOSI输出
     可能在字节间隙出现低电平毛刺, 导致卡状态机错乱
   - 教程源码同样采用此方案: TF_Send_clocks()先将MOSI切Input再发0xFF时钟脉冲
4. SD_SendClocks(): 发送n×8个空闲时钟脉冲(MOSI保持高), 用于:
   - 上电同步(≥74个时钟, 实发30×8=240个)
   - 命令间隔离(CS释放后补2×8=16个)
   - ACMD41成功后补50×8=400个(卡内部状态切换需要时钟)
   - 提速后补50×8=400个(卡适应新时钟频率)
5. 命令发送流程(SD_SendCmd/SD_SendCmdRaw):
   - CS_LOW → MOSI切AF → 发6字节命令 → MOSI切Idle → 1字节空闲时钟 → 读R1响应
   - CS_HIGH → SendClocks(2)
   - CMD0 CRC=0x95, CMD8 CRC=0x87, 其余命令CRC=0x01(正点原子风格)
6. 写单块时序(SD_ReadWriteBlock, is_write=1):
   - CMD24响应0x00后: SendClocks(2) → MOSI切AF → 0xFE起始token → 512字节数据
     → 2字节CRC(0xFF) → MOSI切Idle → 读数据响应(XXX00101=成功) → 忙检测(读到0xFF=完成)
   - 教程明确要求CMD24响应后、发0xFE前补时钟脉冲, 缺失则卡不响应写数据阶段
7. 初始化流程(SD_Init):
   - GPIO/SPI初始化 → 卡插入检测 → MISO线路诊断(INPUT_PU读确认线通→切回AF_INPUT)
   - GoIdle: 240个同步时钟 → CMD0(0x01=空闲) → CMD8(0x01+01AA=SD V2.0)
   - CMD55+ACMD41循环(最多10000次, HCS=1), 成功后SendClocks(50)
   - SDHC类型判定: ACMD41(HCS=1)被接受即SDHC, 不依赖CMD58
   - 去掉CMD59(关CRC)和CMD16(设块长度): SPI模式CRC默认关闭, SDHC块长度固定512
8. 自检(SD_SelfTest): 初始化→写扇区0x003FFFFF(32GB卡倒数第一扇区,不破坏MBR)
   →读回→512字节逐字节校验, 实测PASS
9. 多扇区读写(SD_ReadMultiSector/SD_WriteMultiSector): CMD18/CMD25, 同样MOSI管理

关键发现:
- SPI Mode0(CPOL_Low,CPHA_1Edge)下CMD24返回0xFF(无响应), 切Mode3后立即正常
  → CH32H417 SPI外设Mode0时序与SD卡SPI协议不兼容, 必须用Mode3
- MOSI空闲管理是SD卡SPI驱动的核心要点: AF模式下MOSI在字节间隙可能被拉低,
  违反SD卡"Din无数据时应保持高电平"的要求, 导致卡状态机错乱不响应命令
- ACMD41循环次数不稳定(1~42次), 说明卡初始化耗时变化大, 循环上限必须足够大

必要性:
- BOARD_V2硬件已预留SD卡座(SPI1复用OLED引脚+新增MISO/CD), 驱动是硬件验证前提
- SD卡存储是EEG数据本地记录的基础功能, 规范性要求第8条"SD卡尚未实现"需更新
