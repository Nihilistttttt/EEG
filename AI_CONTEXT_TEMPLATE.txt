## 1.1 核心目标

构建一套完整的脑电波(EEG)采集与稳态视觉诱发电位(SSVEP)方向识别训练系统，
实现从信号采集、特征提取、模型训练到实时推理的全链路闭环。

## 1.2 业务背景

- 应用场景：SSVEP脑机接口(BCI)方向识别（左/右手想象运动）
- 用户流程：佩戴EEG头带 → 校准采集 → 训练模型 → 实时推理反馈
- 核心指标：方向识别准确率、推理延迟、系统稳定性

## 1.3 系统组成

| 组件 | 角色 | 技术栈 | 状态 |
|------|------|--------|------|
| CH32H417 V3F核 | 采集主控+外设管理 | C, RISC-V, SPI/DMA/USART | 稳定运行 |
| CH32H417 V5F核 | 信号处理+推理后端 | C, RISC-V, FPU, FFT | IPC已通 |
| Android客户端 | 波形显示+训练控制+推理展示 | 待定(Kotlin推荐) | 旧版Java待重构 |

## 2.1 硬件平台

- MCU: CH32H417 (沁恒, RISC-V双核)
  - V3F: 100MHz, 2级抢占优先级(3位), 管理外设和采集
  - V5F: 100MHz, 8级抢占优先级(3位), 专注DSP和推理
  - 双核共享RAM: 0x20110000~0x2017FFFF
- ADC: ADS1299 (TI, 8通道24位EEG前端, SPI, 最高16kSPS)
- IMU: ICM42605 (TDK, 6轴, SPI)
- 显示: 0.96" OLED (SPI, SSD1306)
- 通信: USART0(DEBUG 115200) + USART1(WiFi/ESP8266)
- 调试: WCH-Link SWD

## 2.2 双核IPC通信架构

```
V3F (采集+外设主控)              V5F (信号处理+推理后端)
┌──────────────────┐              ┌──────────────────┐
│ ADS1299 SPI+DMA  │              │                  │
│ Ring Buffer      │───IPC CH0──→ │ FFT 256pt        │
│ V3F自身推理       │   Bit1通知   │ 特征提取(24维)    │
│ OLED/Serial/WiFi │   Bit0 ACK← │ CSP/方向分类器    │
│ ICM42605 IMU     │              │ 结果写共享slot    │
└──────────────────┘              └──────────────────┘
         │                                │
         └──── 共享RAM 64-slot帧环形缓冲区 ────┘
```

IPC关键机制:
- 通道: IPC_CH0, TxCID1(V5F发)/RxCID0(V3F收)
- Bit1: V3F→V5F通知 | Bit0: V5F→V3F ACK
- ENA/STS/ISR: 全局共享, ISR = ENA & STS (只读)
- AutoEN: 写ENA 0→1自动设STS, 1→1不触发(重要!)
- MSG[0..3]: 4个32位消息寄存器

## 2.3 信号处理流水线

```
ADS1299原始帧(27字节)
  → 代码转电压(uV×1000)
  → 漂移去除(减均值)
  → 50Hz陷波(IIR)
  → 带通滤波(5-40Hz Butterworth)
  → 256点FFT(125样本hop)
  → 24维特征(theta/mu/beta频段功率比)
  → LDA方向分类器(LEFT/RIGHT)
```

## 2.4 串口协议

命令(下行):
  MODE,SET,<n>     - 设置模式(1=COLLECT, 2=INFER, 3=CALIBRATE)
  MODE,TRAIN       - 开始训练
  MODE,TEST         - 开始测试
  TRIAL,LEFT        - 左手试次
  TRIAL,RIGHT       - 右手试次

数据(上行):
  DIRCSV,<label>,<ch0>,...,<ch7>,<feat0>,...,<feat23>
  DIRCFG,<config_json>
  RESULT,window=<n>,dt_ms=<n>,win_rows=<n>,INTENT=<LEFT|RIGHT>,S_LEFT=<n>,S_RIGHT=<n>,CONF=<n>,trained=<0|1>
  IPCDIAG,ack=<n>,notify=<n>,ok=<n>,bad=<n>,v5fhb=<n>,ENA=<X>,STS=<X>,ISR=<X>

## 4.1 采集主循环 (Signal_Analysis.c)

```
ADS1299 DRDY中断 → DMA搬运帧到ring_buffer → 主循环取出帧
  → 写入IPC共享slot → 发IPC通知给V5F
  → V3F自身: 代码转电压→滤波→FFT→特征→推理
  → 串口输出DIRCSV/DIRCFG/RESULT
  → OLED显示方向结果
```

## 4.2 V5F处理流程 (dualcore_ipc.c)

```
IPC CH0中断 → Handler设pending_flag → 主循环DualCore_V5F_MainLoopProcess()
  → 读共享slot帧数据 → 解析8通道代码
  → 代码转电压→漂移去除→50Hz陷波→带通滤波
  → 125样本hop累积→256点FFT→24维特征
  → LDA分类器推理(LEFT/RIGHT)
  → 结果写回共享slot → 设ack_ready → 下次Handler内发ACK
```

## 4.3 IPC通信时序（已验证通过）

```
时间 →
V3F: ──ENABLE Bit1──────────────────────────────ENABLE Bit1────
V5F:       ──Handler:DISABLE Bit1+设flag──  ──Handler:DISABLE Bit1+发ACK(Bit0)──
V3F:                                              ──Handler:处理ACK+DISABLE Bit0──
V5F主循环:              ──DSP+推理+设ack_ready──
```

关键: V5F的ACK在Handler内发送(MIE=0不自触中断), 延迟1帧

## 4.4 训练流程

```
REST(5s) → LEFT(试次) → REST → RIGHT(试次) → REST → ... 重复
每试次: 采集2s数据 → 提取特征 → 累积到训练集
训练触发: 累积足够样本 → LDA拟合 → 模型参数更新
测试: 使用训练好的模型实时推理 → 输出LEFT/RIGHT+置信度
```

## 5.5 IPC开发铁律（必须遵守）

1. V5F发ACK必须在Handler内(非主循环), 防止自触中断风暴
2. V3F Handler DISABLE Bit0必须在if块内(条件性), 防止误杀ACK
3. V5F发ACK前必须 DISABLE→ENABLE→SetFlagStatus 三步, 确保STS=1
4. V5F Init不能ClearFlagStatus(Bit0), 保留V3F设置的STS
5. 禁止在IPC ENABLE操作周围使用NVIC_DisableIRQ+busy-wait(会死锁)

## 6.1 已知限制

| # | 限制 | 影响 | 优先级 |
|---|------|------|--------|
| 1 | 共享slot无HSEM互斥保护 | parse_ok仅25%, V5F写slot时V3F可能读到不一致数据 | 高 |
| 2 | ENA寄存器read-modify-write非原子 | 双核并发写ENA可能丢失更新 | 中 |
| 3 | V5F ACK延迟1帧 | V3F读到的结果总是上一帧的 | 低(可接受) |
| 4 | Signal_Analysis.c 2450行未拆分 | 维护困难 | 中 |
| 5 | dualcore_ipc.c 1297行未拆分 | 维护困难 | 中 |
| 6 | Android客户端为旧版Java | 功能不全, 需重构 | 高 |

## 6.2 已踩过的坑（新AI必读）

1. **中断风暴**: V5F从主循环ENABLE Bit0→触发自身CH0 Handler→不清Bit0→无限重入
   修复: ACK改为Handler内发送

2. **误杀ACK**: V3F Handler无条件DISABLE Bit0→清除V5F刚设的ENA→V3F永远检测不到ACK
   修复: DISABLE移回if块内

3. **STS=0问题**: V5F Init清STS Bit0 + AutoEN在ENA已为1时不触发 → ISR=0 → V3F无中断
   修复: 移除ClearFlagStatus + DISABLE+ENABLE+SetFlagStatus

4. **NVIC死锁**: 双方NVIC_DisableIRQ+busy-wait互相等待对方清ENA位
   修复: 不用NVIC屏蔽, 改Handler内发ACK

5. **CH0/CH1分用**: 尝试过CH0通知+CH1 ACK, 调试代价远超收益, 已回退到CH0单通道
