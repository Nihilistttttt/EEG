## 1.1 核心目标

构建一套完整的脑电波(EEG)采集与稳态视觉诱发电位(SSVEP)方向识别训练系统，
实现从信号采集、特征提取、模型训练到实时推理的全链路闭环。

## 1.2 业务背景

- 应用场景：SSVEP脑机接口(BCI)方向识别（左/右手想象运动）+ 专注度/放松度监测
- 用户流程：佩戴EEG头带 → 校准采集 → 训练模型 → 实时推理反馈
- 核心指标：方向识别准确率、推理延迟、专注度判别准确性、系统稳定性

## 1.3 系统组成

| 组件 | 角色 | 技术栈 | 状态 |
|------|------|--------|------|
| CH32H417 V3F核 | 采集主控+专注度算法+外设管理 | C, RISC-V, SPI/DMA/USART | 稳定运行 |
| CH32H417 V5F核 | 信号处理+方向推理后端 | C, RISC-V, FPU, Goertzel | IPC已通 |
| Android医生端 | 波形显示+训练控制+推理展示 | Java, TCP/WiFi | SSVEP/MI训练分离 |
| Android患者端 | 被动接收训练指令+推理展示 | Java, TCP/WiFi | 被动化改造完成 |

## 2.1 硬件平台

- MCU: CH32H417 (沁恒, RISC-V双核)
  - V3F: 100MHz, 管理外设、采集、专注度算法
  - V5F: 100MHz, FPU启用, 专注DSP和方向推理
  - 双核共享RAM: 0x20110000~0x2017FFFF (448KB)
- ADC: ADS1299 (TI, 8通道24位EEG前端, SPI+DMA, 250SPS)
- IMU: ICM42605 (TDK, 6轴, SPI)
- 显示: 0.96" OLED (SPI, SSD1306)
- 通信: USART0(DEBUG 115200) + USART1(WiFi/ESP8266)
- 调试: WCH-Link SWD

## 2.2 双核IPC通信架构

```
V3F (采集+专注度+外设主控)          V5F (信号处理+方向推理后端)
┌──────────────────────┐              ┌──────────────────────┐
│ ADS1299 SPI+DMA      │              │                      │
│ Ring Buffer           │───IPC CH0──→ │ Goertzel频谱         │
│ FFT 256pt + 专注度    │   Bit1通知   │ 24维特征提取          │
│ OLED/Serial/WiFi      │   Bit0 ACK← │ SVM/CSP方向分类器     │
│ ICM42605 IMU          │              │ 结果写共享slot        │
└──────────────────────┘              └──────────────────────┘
         │                                    │
         └──── 共享RAM 64-slot帧环形缓冲区 ────┘
```

IPC关键机制:
- 通道: IPC_CH0, TxCID1(V5F发)/RxCID0(V3F收)
- Bit1: V3F→V5F通知 | Bit0: V5F→V3F ACK
- ENA/STS/ISR: 全局共享, ISR = ENA & STS (只读)
- AutoEN: 写ENA 0→1自动设STS, 1→1不触发(重要!)
- MSG[0..3]: 4个32位消息寄存器

## 2.3 V3F信号处理流水线（专注度）

```
ADS1299原始帧(27字节)
  → 代码转电压(uV×1000)
  → 漂移去除(减均值+线性去趋势)
  → 50Hz陷波(IIR Biquad, 共享系数)
  → 带通滤波(5-40Hz Butterworth, 共享系数)
  → 256点FFT(125样本hop, 静态内存分配)
  → 4通道加权融合(C3/C4权重0.6, CP3/CP4权重0.4)
  → 多特征专注度评分: 0.45*log(β/(α+θ)) + 0.35*log(β/α) + 0.20*log(δ/θ)
  → P²在线分位数归一化 + EMA平滑 + 跳变检测
  → 软分类(NEUTRAL/FOCUS/RELAX) + trend_state(8分死区)
```

## 2.4 V5F信号处理流水线（方向推理）

```
共享slot帧数据
  → 代码转电压
  → 漂移去除(减均值+线性去趋势)
  → 50Hz陷波(IIR SOS, 共享系数)
  → 带通滤波(5-40Hz, 共享系数)
  → Goertzel频谱(只算目标频点, 比FFT高效)
  → 24维log-ratio特征
  → Linear SVM / CSP-SVM分类器
  → 4窗口EMA融合 + UNKNOWN门限12%
```

## 2.5 串口协议

命令(下行):
  MODE,SET,<n>     - 设置模式(1=COLLECT, 2=COLLECT_CSP, 3=INFER)
  MODE,TRAIN       - 开始训练
  MODE,TEST         - 开始测试
  TRIAL,LEFT        - 左手试次
  TRIAL,RIGHT       - 右手试次
  STOP              - 停止当前模式, 重置推理状态
  IPCDIAG,ON/OFF    - IPC诊断开关

数据(上行):
  FOCUS,<attn>,<relax>,<conf>,<trend>,<instant>
  DIRCSV,<label>,<ch0>,...,<ch7>,<feat0>,...,<feat23>
  RESULT,src=V5F,window=<n>,dt_ms=<n>,win_rows=<n>,INTENT=<LEFT|RIGHT|UNKNOWN>,S_LEFT=<n>,S_RIGHT=<n>,CONF=<n>,trained=<0|1>
  IPCDIAG,ack=<n>,notify=<n>,ok=<n>,bad=<n>,v5fhb=<n>,ENA=<X>,STS=<X>,ISR=<X>

## 4.1 V3F采集主循环 (Signal_Analysis.c → 各模块)

```
ADS1299 DRDY中断 → DMA搬运帧到ring_buffer → 主循环取出帧
  → 写入IPC共享slot → 发IPC通知给V5F
  → V3F自身: FFT状态机(分步执行) → 专注度/放松度评分 → 串口输出FOCUS
  → INFER模式: 读取V5F推理结果 → 串口输出RESULT,src=V5F
  → COLLECT模式: 输出DIRCSV特征数据
```

## 4.2 V5F处理流程 (dualcore_ipc_v5f.c → dualcore_v5f_dsp.c)

```
IPC CH0中断 → Handler设pending_flag → 主循环DualCore_V5F_MainLoopProcess()
  → 读共享slot帧数据 → 解析4通道代码
  → 代码转电压→漂移去除→50Hz陷波→带通滤波(IIR系数共享)
  → Goertzel频谱(只算目标频点)→24维log-ratio特征
  → SVM/CSP分类器推理(LEFT/RIGHT/UNKNOWN)
  → 4窗口EMA融合 → 结果写回共享slot → 设ack_ready → Handler内发ACK
```

## 4.3 专注度算法 (algo_core.c)

```
4通道频段功率 → 加权融合(C3/C4:0.6, CP3/CP4:0.4)
  → 多特征评分: 0.45*fast_logf(β/(α+θ)) + 0.35*fast_logf(β/α) + 0.20*fast_logf(δ/θ)
  → P²在线分位数归一化(P10/P90基线)
  → EMA平滑(α=0.25) + 跳变检测(阈值40, α=0.1)
  → 伪迹检测: 200μV阈值 + 30%坏窗口降级 + 连续5次Invalid
  → 软分类: confidence<15%→NEUTRAL, attn>60→FOCUS, relax>60→RELAX
  → trend_state: 窗口均值差+8分死区
```

## 4.4 IPC通信时序（已验证通过）

```
时间 →
V3F: ──ENABLE Bit1──────────────────────────────ENABLE Bit1────
V5F:       ──Handler:DISABLE Bit1+设flag──  ──Handler:DISABLE Bit1+发ACK(Bit0)──
V3F:                                              ──Handler:处理ACK+DISABLE Bit0──
V5F主循环:              ──DSP+推理+设ack_ready──
```

关键: V5F的ACK在Handler内发送(MIE=0不自触中断), 延迟1帧

## 5.5 IPC开发铁律（必须遵守）

1. V5F发ACK必须在Handler内(非主循环), 防止自触中断风暴
2. V3F Handler DISABLE Bit0必须在if块内(条件性), 防止误杀ACK
3. V5F发ACK前必须 DISABLE→ENABLE→SetFlagStatus 三步, 确保STS=1
4. V5F Init不能ClearFlagStatus(Bit0), 保留V3F设置的STS
5. 禁止在IPC ENABLE操作周围使用NVIC_DisableIRQ+busy-wait(会死锁)
6. HSEM互斥保护已尝试3次均卡死, 已放弃, 当前用DUALCORE_FENCE()内存屏障

## 6.3 已踩过的坑（新AI必读）

1. **中断风暴**: V5F从主循环ENABLE Bit0→触发自身CH0 Handler→无限重入
   修复: ACK改为Handler内发送

2. **误杀ACK**: V3F Handler无条件DISABLE Bit0→清除V5F刚设的ENA
   修复: DISABLE移回if块内

3. **STS=0问题**: V5F Init清STS Bit0 + AutoEN在ENA已为1时不触发→ISR=0
   修复: 移除ClearFlagStatus + DISABLE+ENABLE+SetFlagStatus三步

4. **NVIC死锁**: 双方NVIC_DisableIRQ+busy-wait互相等待
   修复: 不用NVIC屏蔽, 改Handler内发ACK

5. **ACK历史索引bug**: V3F CH0 Handler用slot_idx=seq%64索引256项历史表,
   但V3F写入时用hist_idx=seq%256, seq≥64时索引错位
   修复: 统一为seq%256

6. **HSEM互斥**: 尝试过3次(HSEM_DataSharing方案), 均卡死, 已放弃
   原因: try-lock死循环/spin-lock无效/HSEM中断优先级冲突

7. **fast_logf查找表偏移bug**: 表存储ln(m+0.5)但公式用exponent*ln(2),
   导致所有log计算结果偏移-ln(2)≈-0.693
   修复: 重新生成正确的ln(1+m)表

## 8.2 fast_logf查找表

```c
// 256项 ln(1+m) 表, m ∈ [0, 1)
// IEEE754位操作: exponent = (raw>>23)-127, mantissa = raw&0x7FFFFF
// m = mantissa/2^23, 查表+线性插值得ln(1+m)
// 结果 = ln(1+m) + exponent*ln(2)
// 最大误差 ~1.2e-6
```

## 8.3 FFT静态分配

```c
static uint8_t s_fft_mem_pool[4096] __attribute__((aligned(4)));
// 先查询所需大小, 不足则while(1)死锁保护

```

## 8.4 专注度特征公式

```
attention_score  = 0.45 * fast_logf(β/(α+θ)) + 0.35 * fast_logf(β/α) + 0.20 * fast_logf(δ/θ)
relaxation_score = fast_logf(α/θ)
```
4通道加权融合: `fused = 0.4*(CH0+CH1) + 0.6*(CH2+CH3)`

## 8.5 V5F方向特征

24维log-ratio特征:
- 8维同侧频段比(theta/beta ch0-ch3 vs ch0-ch3)
- 8维频段占比比(mu/beta vs total)
- 4维跨侧频段比(mu/beta ch0/ch1 vs ch2/ch3)
- 4维跨侧同频段比(mu/beta ch0/ch2, ch1/ch3)
